# 1. 보급로, 무엇을 구해야 할까?

## Slide 2. 어떤 문제인가?

### 목적
이 슬라이드에서는 문제 원문을 길게 설명하지 않고, **문제 상황과 핵심 규칙만 먼저 이해시키는 것**을 목표로 한다.

### 발표 순서
발표할 때는 다음 순서로 설명한다.

1. **왜 도로를 복구해야 하는가**
2. **복구 시간은 무엇으로 결정되는가**
3. **지도에서는 어떻게 이동하는가**
4. **결국 무엇을 최소화해야 하는가**

---

### 1. 문제 상황
전투로 인해 도로 곳곳이 파손되어 차량이 바로 이동할 수 없는 상황이다.

공병대는 출발지 `S`에서 도착지 `G`까지 이동할 수 있도록 도로를 복구해야 한다.

여기서 중요한 조건은:

> 도로가 깊게 파손될수록 복구 시간이 더 오래 걸린다.

예를 들어:

```text
도로 깊이 1 → 복구 시간 1
도로 깊이 3 → 복구 시간 3
```

---

### 2. 지도에서의 이동
지도는 `N × N` 크기의 2차원 배열로 표현된다.

- 출발점 `S` : 좌상단 `(0,0)`
- 도착점 `G` : 우하단 `(N-1,N-1)`
- 한 번에 한 칸 이동
- 이동 가능 방향 : **상 / 하 / 좌 / 우**

각 칸의 숫자는 해당 위치의 **도로 파손 깊이 = 복구 시간**을 의미한다.

값이 `0`이면 해당 위치에서는 복구 시간이 들지 않는다.

---

### 3. 이 문제에서 중요한 것
문제에서는 차량의 **이동 시간 자체는 무시할 수 있을 만큼 작다**고 가정한다.

따라서 이동 횟수나 이동 거리를 최소화하는 문제가 아니다.

핵심은:

> **S에서 G까지 가는 경로 중, 지나가는 도로의 총 복구 시간이 가장 작은 경로를 찾는 것**

이다.

### 슬라이드에 실제로 넣을 텍스트
PPT에는 아래 정도만 넣는 것을 추천한다.

**도로 복구**
```text
파손 깊이 = 복구 시간
```

**이동**
```text
S → G
상 / 하 / 좌 / 우
```

**목표**
```text
총 복구 시간이 최소인 경로
```

나머지는 발표자가 말로 설명한다.

---

### 발표 멘트 흐름 예시

> “도로가 파손되어 있기 때문에 차량이 이동하려면 먼저 도로를 복구해야 합니다.”

> “그리고 파손된 깊이가 깊을수록 복구 시간이 더 오래 걸립니다.”

> “지도는 N×N 격자로 주어지고, 좌상단 S에서 우하단 G까지 상하좌우로 이동할 수 있습니다.”

> “여기서 이동 시간 자체는 무시하기 때문에, 가장 적게 이동하는 길이 아니라 **복구 시간의 합이 가장 작은 길**을 찾는 것이 이 문제의 목표입니다.”

### 발표 포인트
문제 소개에서 입력/출력 형식이나 시간 제한까지 전부 읽지 않는다.

이 슬라이드에서 청중이 기억해야 하는 것은 딱 세 가지다.

```text
① 칸마다 복구 비용이 있다.
② 상하좌우로 이동한다.
③ 총 복구 비용을 최소화한다.
```

---

## Slide 3. 문제를 알고리즘 관점으로 바꿔보기

### 목적
문제의 스토리를 알고리즘 조건으로 정리하고, 다음 슬라이드의 `BFS로 풀 수 있을까?`라는 질문으로 연결한다.

### 문제 조건 정리

| 문제 속 표현 | 알고리즘 관점 |
|---|---|
| `N × N` 지도 | 2차원 격자 |
| 출발지 `S` | `(0,0)` |
| 도착지 `G` | `(N-1,N-1)` |
| 상하좌우 이동 | 인접한 칸으로 이동 |
| 도로 깊이 | 해당 칸의 이동 비용 |
| 복구 시간의 합 | 누적 비용 |
| 가장 빠른 복구 | 누적 비용의 최솟값 |

### 알고리즘 선택에 중요한 조건

#### 조건 1. 이동 횟수를 최소화하는 문제가 아니다
문제에서 이동 시간은 고려하지 않는다.

따라서:

```text
짧은 경로 = 정답
```

이라고 볼 수 없다.

---

#### 조건 2. 칸마다 비용이 다르다
각 칸에는 `0~9`의 서로 다른 복구 시간이 존재한다.

즉:

```text
모든 이동 비용이 동일한 격자 탐색
```

이 아니라

```text
위치마다 서로 다른 비용이 존재하는 격자 탐색
```

이다.

---

#### 조건 3. 비용은 모두 0 이상이다
복구 시간은 `0~9`이므로 음수 비용은 존재하지 않는다.

이 조건은 이후 다익스트라를 선택하는 중요한 근거가 된다.

---

### 이 시점에서 문제를 한 줄로 바꾸면

> **상하좌우로 이동할 수 있는 가중치 격자에서, 시작점부터 도착점까지의 최소 누적 비용을 구하는 문제**

### 다음 슬라이드 연결

이제 자연스럽게 다음 질문으로 넘어간다.

> **“격자에서 S에서 G까지 가는 문제니까 BFS로 풀면 되지 않을까?”**

이 질문을 던진 뒤, 다음 슬라이드에서 BFS가 왜 적합하지 않은지 반례를 보여준다.

### PPT 구성 제안
이 슬라이드는 텍스트를 많이 넣기보다 아래 흐름만 시각적으로 보여준다.

```text
N × N 격자
   +
상하좌우 이동
   +
칸마다 서로 다른 비용
   +
누적 비용 최소화
```

그리고 마지막에 크게:

```text
어떤 알고리즘을 사용해야 할까?
```

### 발표 포인트
이 장에서는 아직 `Dijkstra`라는 이름을 크게 꺼내지 않는다.

청중이 먼저 문제의 특징을 보고,
다음 장에서 BFS를 검토하고 탈락시키는 사고 과정을 따라오게 만든다.

# 2. 각 위치를 지날 때 드는 비용이 서로 다르다
각 칸의 값이 `0~9`이므로 이동하는 위치에 따라 비용이 달라진다.

즉 이 문제는 단순한:

> 최소 이동 횟수 문제

가 아니라:

> **가중치가 존재하는 최소 비용 경로 문제**

로 볼 수 있다.

#### 3. 비용은 음수가 아니다
각 칸의 복구 시간은 `0~9`이므로 음수 비용이 존재하지 않는다.

이 조건은 이후 다익스트라를 선택하는 중요한 근거가 된다.

### 이 시점의 문제 정의

```text
시작점 : (0, 0)

목적지 : (N-1, N-1)

이동   : 상 / 하 / 좌 / 우

비용   : 이동한 칸의 map 값

목표   : 시작점 → 목적지 누적 비용 최소화
```

### 다음 슬라이드로 넘길 질문

> **격자에서 목적지까지 가는 문제니까 BFS를 사용하면 되지 않을까?**

### 시각화 / 레이아웃
추천 구성:

- 왼쪽: 문제 속 실제 지도
- 가운데: `스토리 제거`
- 오른쪽: 숫자가 적힌 `N × N` 격자
- 하단: `누적 비용 최소화`를 크게 강조

시각적으로:

```text
파손된 도로 문제
      ↓
N × N 격자
      ↓
칸마다 서로 다른 비용
      ↓
최소 누적 비용 경로
```

형태로 정리한다.

### 발표 포인트
이 장의 역할은 **다익스트라를 설명하는 것이 아니다.**

문제에서 어떤 조건을 읽어냈는지 보여준 뒤,
다음 장에서 `BFS → 반례 → 가중치 최단 경로 → Dijkstra` 순으로 알고리즘을 판단한다.

# 2. 어떤 알고리즘을 선택해야 할까?

## Slide 4. 첫 번째 생각 — BFS?

### 목적
격자 문제를 보고 자연스럽게 BFS를 떠올리는 사고 과정을 보여준다.

### 핵심 내용
- 격자에서 시작점 → 도착점
- 상하좌우 이동
- 일반적인 최단 경로 문제에서는 BFS가 자주 사용됨

### 질문
> 격자 최단 경로니까 BFS로 풀 수 있을까?

### BFS 특징
- 시작점에서 가까운 위치부터 탐색
- 모든 이동 비용이 동일하다면 최소 이동 횟수를 보장

### 전환
> 하지만 보급로에서는 칸마다 비용이 다르다.

### 시각화 / 레이아웃
- BFS가 거리 0 → 거리 1 → 거리 2 순서로 퍼지는 그림
- 하단에 `BUT` 또는 문제점 강조

### 발표 포인트
“격자니까 BFS”라는 자동적인 판단을 한 번 의심하는 과정이 중요하다.

---

## Slide 5. BFS로 풀면 왜 안 될까?

### 목적
반례를 통해 BFS를 사용할 수 없는 이유를 확실하게 설명한다.

### 핵심 반례

경로 A:
- 이동 횟수 적음
- 복구 비용 큼

경로 B:
- 이동 횟수 많음
- 복구 비용 작음

예시:

```text
경로 A: 3번 이동, 비용 18
경로 B: 5번 이동, 비용 4
```

### 결론
> 더 적게 이동한다고 더 저렴한 경로인 것은 아니다.

```text
최소 이동 횟수 ❌
최소 누적 비용 ⭕
```

### 시각화 / 레이아웃
- 하나의 시작점에서 두 경로가 갈라지는 그림
- 각 경로 옆에 이동 횟수와 비용 표시

### 발표 포인트
BFS가 잘못된 알고리즘이라기보다, **BFS가 최적을 보장하는 조건이 이 문제와 다르다**고 설명한다.

---

## Slide 6. 이 문제를 그래프로 바라보면?

### 목적
격자 문제를 가중치 그래프로 해석하고 다익스트라까지 연결한다.

### 핵심 대응

```text
칸        → 정점(Vertex)
상하좌우   → 간선(Edge)
복구 시간  → 가중치(Weight)
```

### 사고 흐름

```text
최소 비용을 구한다
        ↓
이동마다 비용이 존재한다
        ↓
가중치가 있는 최단 경로 문제
        ↓
가중치는 모두 0 이상
        ↓
Dijkstra
```

### 시각화 / 레이아웃
- 왼쪽: 격자
- 오른쪽: 같은 구조를 노드와 간선으로 표현한 간단한 그래프
- 하단: 알고리즘 판단 흐름

### 발표 포인트
“이 문제는 다익스트라 문제라서 다익스트라를 썼다”가 아니라,
**왜 다익스트라까지 도달했는지**를 보여주는 핵심 슬라이드다.

# 3. 다익스트라는 어떻게 동작할까?

> 이 파트는 다익스트라 코드를 먼저 보여주는 것이 아니라,  
> **알고리즘이 실제로 어떤 순서로 움직이는지 눈으로 이해시키는 것**을 목표로 한다.
>
> 최종 발표에서는 이 부분을 정적인 슬라이드보다 **웹 기반 단계별 시각화**로 보여주는 방향을 우선 고려한다.

---

## 이 파트의 설명 순서

```text
1. 현재까지 비용이 가장 작은 정점을 선택한다.
            ↓
2. 그 정점에서 갈 수 있는 정점을 확인한다.
            ↓
3. 현재 정점을 거쳐 갈 때의 새로운 비용을 계산한다.
            ↓
4. 기존 비용보다 더 작으면 dist를 갱신한다.
            ↓
5. 갱신된 정점을 PriorityQueue에 넣는다.
            ↓
6. 다시 비용이 가장 작은 정점을 선택한다.
```

이 흐름을 먼저 시각적으로 보여준 뒤,
`dist`, `PriorityQueue`, `Relaxation` 개념과 Java 코드로 연결한다.

---

## 다익스트라 설명용 예제 그래프

다익스트라의 동작을 설명할 때는 아래 방향 그래프 하나를 끝까지 사용한다.

```text
1 → 2  (3)
1 → 3  (2)
1 → 4  (5)

2 → 3  (2)
2 → 5  (8)

3 → 4  (2)

4 → 5  (6)

5 → 6  (1)
```

- 시작 정점: `1`
- 간선은 **방향이 있는 간선**
- 괄호 안 숫자는 간선 비용

### 이 예제를 사용하는 이유

이 그래프에서는 다익스트라의 핵심 상황이 모두 자연스럽게 발생한다.

| 설명할 개념 | 실제 발생하는 상황 |
|---|---|
| 시작점 초기화 | `dist[1] = 0` |
| PQ에서 최소값 선택 | `3(2)`가 `2(3)`보다 먼저 선택 |
| 처음 거리 발견 | `dist[4] = 5` |
| 더 짧은 경로 발견 | `dist[4] : 5 → 4` |
| 갱신하지 않는 경우 | `2 → 3` 경로 비용 `5 > 기존 2` |
| 다시 더 짧은 경로 발견 | `dist[5] : 11 → 10` |
| 최종 최소 비용 | `dist[6] = 11` |

따라서 예제를 중간에 바꾸지 않고,
**이 그래프 하나로 PriorityQueue → dist → Relaxation → 최종 결과까지 설명**한다.

> 현재 사용자가 제공한 이미지는 참고용이며,  
> 실제 웹 발표에서는 디자인 톤에 맞춰 그래프를 새로 그린다.

## Slide / Scene 7. 다익스트라의 핵심 아이디어

### 목적
다익스트라의 핵심을 한 문장으로 먼저 이해시킨다.

### 핵심 문장
> **현재까지 발견한 경로 중, 누적 비용이 가장 작은 정점부터 탐색한다.**

시작 정점 `1`에서 한 번 탐색한 뒤 후보가 다음과 같다고 하자.

```text
2 : 3
3 : 2
4 : 5
```

다음 탐색 대상은 `3`.

이유:

```text
2 < 3 < 5
```

이므로 현재까지 가장 저렴하게 도달할 수 있는 정점이 `3`이기 때문이다.

### 강조할 점
다익스트라는:

> 번호가 작은 정점

이나

> 시작점에서 바로 가까운 정점

을 먼저 보는 알고리즘이 아니다.

> **현재까지의 누적 비용이 가장 작은 정점**

을 먼저 본다.

이 차이가 BFS와 다익스트라를 구분하는 중요한 포인트다.

## Slide / Scene 8. 왜 PriorityQueue가 필요할까?

### 목적
PriorityQueue를 단순 구현 도구가 아니라,
다익스트라의 핵심 동작을 수행하기 위한 자료구조로 이해시킨다.

다익스트라는 매번:

> 현재 후보 중 누적 비용이 가장 작은 정점

을 골라야 한다.

그래서:

```java
PriorityQueue<Node>
```

를 사용한다.

### 예제 그래프에서의 상태

정점 `1`을 확인한 직후:

```text
Priority Queue
──────────────
3          2   ← 다음 선택
2          3
4          5
```

### 의미
> 아직 확인해야 할 경로 후보를 저장하고,  
> 그중 **누적 비용이 가장 작은 후보를 먼저 꺼낸다.**

### 웹 시각화
- 오른쪽 상태 패널에 PriorityQueue를 항상 표시
- `3 : 2` 카드가 가장 위에 위치
- 다음 단계에서 카드가 PQ 밖으로 빠져나옴
- 동시에 그래프의 `3`번 정점이 활성화됨

### 발표 멘트 핵심
> “다익스트라는 매 순간 현재까지 가장 싼 후보를 선택해야 하기 때문에 PriorityQueue를 사용합니다.”

## Slide / Scene 9. dist는 무엇을 저장할까?

### 목적
`dist` 배열의 의미를 확실히 이해시킨다.

```java
dist[v]
```

는:

> 시작점에서 `v`까지 가는 데  
> **현재까지 발견한 최소 비용**

을 저장한다.

### 초기 상태

시작 정점이 `1`이므로:

```text
1 : 0
2 : ∞
3 : ∞
4 : ∞
5 : ∞
6 : ∞
```

즉:

```java
dist[1] = 0;
```

나머지는 충분히 큰 값으로 초기화한다.

### 웹 시각화
각 정점 위에 현재 `dist` 값을 표시한다.

초기 상태:

```text
  0
 [1]

  ∞
 [2]

  ∞
 [3]
```

새로운 경로를 발견하면:

```text
∞ → 3
∞ → 2
∞ → 5
```

처럼 값이 바뀌는 모습을 보여준다.

### 발표 멘트 핵심
`dist`를 방문 여부가 아니라:

> **현재까지 알고 있는 가장 싼 가격표**

라고 설명한다.

## Slide / Scene 10. 실제로 한 단계씩 움직여보기

### 목적
`PriorityQueue`, `dist`, 간선 탐색이 어떻게 연결되는지 예제 그래프에서 직접 보여준다.

---

### STEP 0. 초기화

시작 정점:

```text
1
```

초기 `dist`:

```text
1 = 0
2 = ∞
3 = ∞
4 = ∞
5 = ∞
6 = ∞
```

PriorityQueue:

```text
1 : 0
```

### 웹에서는
- `1`번 정점 활성화
- `dist[1] = 0`
- 나머지는 `∞`
- PriorityQueue에 `1 : 0`

---

### STEP 1. 1번 정점 선택

PriorityQueue에서:

```text
1 : 0
```

을 꺼낸다.

현재 정점:

```text
1
```

`1`에서 갈 수 있는 정점은:

```text
1 → 2  (3)
1 → 3  (2)
1 → 4  (5)
```

---

### STEP 2. 1 → 2 확인

현재:

```text
dist[1] = 0
weight(1,2) = 3
```

새로운 비용:

```text
0 + 3 = 3
```

기존:

```text
dist[2] = ∞
```

따라서:

```text
dist[2] = 3
```

PriorityQueue에:

```text
2 : 3
```

추가.

### 웹에서는
- `1 → 2` 간선 강조
- 작은 빛 또는 점이 `1`에서 `2`로 이동
- `0 + 3 = 3`
- `dist[2] : ∞ → 3`
- PQ에 `2 : 3` 카드 추가

---

### STEP 3. 1 → 3 확인

```text
0 + 2 = 2
```

따라서:

```text
dist[3] = 2
```

PriorityQueue:

```text
3 : 2
2 : 3
```

---

### STEP 4. 1 → 4 확인

```text
0 + 5 = 5
```

따라서:

```text
dist[4] = 5
```

PriorityQueue:

```text
3 : 2
2 : 3
4 : 5
```

### 여기서 청중에게 질문

> 다음에는 2, 3, 4 중 어떤 정점을 탐색해야 할까?

정답:

```text
3
```

이유:

```text
dist[3] = 2
dist[2] = 3
dist[4] = 5
```

즉:

> **현재까지 가장 비용이 작은 후보부터 탐색한다.**

를 다시 강조한다.

## Slide / Scene 11. 첫 번째 핵심 갱신 — dist[4] : 5 → 4

### 목적
다익스트라의 핵심인 `Relaxation`을 실제 상황으로 설명한다.

현재 PriorityQueue의 최소값:

```text
3 : 2
```

따라서 `3`번 정점을 선택한다.

`3`에서 갈 수 있는 곳:

```text
3 → 4  (2)
```

현재까지 `3`에 오는 비용:

```text
dist[3] = 2
```

새로운 경로:

```text
2 + 2 = 4
```

그런데 기존에는:

```text
dist[4] = 5
```

였다.

비교:

```text
새 경로 4 < 기존 경로 5
```

따라서:

```text
dist[4]

5 → 4
```

로 갱신한다.

### 핵심 문장
> **처음 발견한 경로가 최종 경로라는 보장은 없다.**

> **더 저렴한 경로를 발견하면 기존 값을 더 작은 값으로 바꾼다.**

이 과정을 `Relaxation`이라고 부른다.

### 웹 시각화
- `3 → 4` 간선 강조
- `2 + 2 = 4` 계산 표시
- 4번 정점 위의 숫자 `5`가 `4`로 변경
- 갱신 성공을 짧게 강조
- `4 : 4`를 PriorityQueue에 다시 추가

### 중요한 구현 포인트
기존의 `4 : 5` 항목이 PriorityQueue 안에 남아 있을 수도 있다.

나중에 꺼냈을 때:

```text
현재 dist[4] = 4
PQ에서 꺼낸 비용 = 5
```

라면 오래된 정보이므로 건너뛸 수 있다.

이 내용은 발표 시간에 따라 구현 팁으로 선택적으로 설명한다.

## Slide / Scene 12. 갱신하지 않는 경우도 있다

### 목적
모든 경로를 발견할 때마다 값을 바꾸는 것이 아니라는 점을 보여준다.

현재 유효 후보:

```text
2 : 3
4 : 4
```

따라서 `2`번 정점을 선택한다.

`2`에서 갈 수 있는 정점:

```text
2 → 3  (2)
2 → 5  (8)
```

### 2 → 3 확인

새로운 비용:

```text
dist[2] + 2
= 3 + 2
= 5
```

기존:

```text
dist[3] = 2
```

비교:

```text
5 > 2
```

따라서:

```text
갱신하지 않음
```

### 핵심 문장
> **새로운 경로가 더 비싸면 기존 최소 비용을 유지한다.**

### 웹 시각화
- `2 → 3` 간선 강조
- `3 + 2 = 5`
- `기존 dist[3] = 2`
- `5 > 2`
- `NO UPDATE` 또는 `그대로 유지`

강조 효과는 갱신 성공보다 약하게 한다.

## Slide / Scene 16. 다익스트라의 한 사이클

### 목적
앞에서 본 여러 단계가 사실 같은 과정을 반복한 것임을 정리한다.

```text
PriorityQueue에서
가장 비용이 작은 정점을 꺼냄
           ↓
갈 수 있는 정점 확인
           ↓
새로운 누적 비용 계산
           ↓
기존 dist보다 작은가?
      ↙           ↘
    YES            NO
     ↓              ↓
dist 갱신         그대로 유지
     ↓
PriorityQueue에 추가
           ↓
다시 반복
```

### 핵심
앞의 `1 → 2`, `1 → 3`, `3 → 4`, `2 → 3`, `4 → 5`는
모두 이 동일한 로직을 반복한 것이다.

## Slide / Scene 17. Java 기본 템플릿

### 목적
지금까지 눈으로 본 동작을 코드로 연결한다.

```java
PriorityQueue<Node> pq = new PriorityQueue<>();

dist[start] = 0;
pq.offer(new Node(start, 0));

while (!pq.isEmpty()) {

    Node cur = pq.poll();

    if (cur.cost > dist[cur.node]) {
        continue;
    }

    for (Edge edge : graph[cur.node]) {

        int nextCost = cur.cost + edge.cost;

        if (nextCost < dist[edge.to]) {
            dist[edge.to] = nextCost;
            pq.offer(new Node(edge.to, nextCost));
        }
    }
}
```

### 코드와 시각화 대응

#### ① 가장 싼 후보 선택
```java
Node cur = pq.poll();
```

→ PQ의 가장 작은 카드가 빠져나오는 장면

#### ② 오래된 PQ 정보라면 건너뛰기
```java
if (cur.cost > dist[cur.node]) {
    continue;
}
```

예:
```text
PQ에는 4 : 5가 남아 있지만
현재 dist[4]는 이미 4
→ 오래된 후보이므로 무시
```

#### ③ 연결된 정점 확인
```java
for (Edge edge : graph[cur.node])
```

→ 현재 정점에서 나가는 방향 간선을 하나씩 강조

#### ④ 새로운 비용 계산
```java
int nextCost = cur.cost + edge.cost;
```

예:
```text
2 + 2 = 4
```

#### ⑤ 더 저렴하면 갱신
```java
if (nextCost < dist[edge.to])
```

예:
```text
dist[4] : 5 → 4
```

#### ⑥ 갱신된 후보 추가
```java
pq.offer(...)
```

→ `4 : 4`가 PQ에 들어가는 장면

### 발표 흐름 원칙

```text
움직임
↓
개념
↓
코드
```

순서로 설명한다.

코드부터 보여주지 않는다.

## 예제 그래프

웹에서는 사용자가 제공한 원본 이미지를 그대로 사용하지 않고, 동일한 구조를 새 디자인으로 다시 제작한다.

반드시 유지:

```text
1 → 2  (3)
1 → 3  (2)
1 → 4  (5)
2 → 3  (2)
2 → 5  (8)
3 → 4  (2)
4 → 5  (6)
5 → 6  (1)
```

방향 화살표와 간선 비용이 가장 먼저 읽혀야 한다.

## 그래프 표현

### Node
- 둥근 원형
- 아주 약한 입체감
- 큰 정점 번호
- 현재 Node만 살짝 Lift
- 필요할 때만 Node 위에 dist 표시

### Edge
- 얇고 명확한 방향 화살표
- Weight를 작은 라벨로 표시
- 현재 확인하는 간선만 Blue 강조
- Source → Target 방향으로 짧은 빛 이동 가능

### 핵심 값 변경

```text
dist[4]
5 → 4
```

```text
dist[5]
11 → 10
```

은 Number transition으로 크게 보여준다.

---

## PriorityQueue 표현

PQ를 모든 슬라이드에 계속 표시하지 않는다.

`왜 PriorityQueue인가?` 또는 실제 실행 과정처럼 필요한 장면에서만 등장시킨다.

```text
3 : 2   ← 최소
2 : 3
4 : 5
```

가장 작은 값이 위로 자연스럽게 정렬되는 Motion을 사용한다.

---

## Relaxation은 별도 집중 슬라이드

화면에 필요한 요소만 남긴다.

```text
dist[3] = 2

3 ──2──▶ 4

NEW = 4
OLD = 5

4 < 5

5 → 4
```

하단에는:

```text
더 싼 경로를 발견하면 갱신한다.
```

정도만 보여준다.

## 일반 그래프 → 보급로 전환

다익스트라 일반 설명 후:

# 4. 다익스트라를 보급로에 적용해보자

## Slide 11. 일반 다익스트라 → 보급로

### 목적
일반적인 그래프 다익스트라를 격자 문제에 어떻게 바꾸는지 보여준다.

### 대응표

| 일반 다익스트라 | SWEA 1249 |
|---|---|
| 정점 `node` | 좌표 `(x, y)` |
| 간선 | 상하좌우 이동 |
| 간선 가중치 | `map[nx][ny]` |
| `dist[node]` | `dist[x][y]` |
| 인접 리스트 | `dx`, `dy` |
| 시작점 | `(0,0)` |
| 목적지 | `(N-1,N-1)` |

### 핵심 문장
> 알고리즘 자체는 그대로이고, 정점을 숫자가 아니라 **좌표로 표현했을 뿐이다.**

### 시각화 / 레이아웃
- 왼쪽 일반 그래프
- 오른쪽 격자
- 가운데 화살표 또는 대응표

### 발표 포인트
격자도 결국 그래프라는 점을 강조한다.

---

## Slide 12. 보급로 코드의 핵심

### 목적
실제 구현 코드가 다익스트라 템플릿과 어떻게 연결되는지 설명한다.

### 핵심 코드

```java
while (!pq.isEmpty()) {

    int[] cur = pq.poll();

    int x = cur[0];
    int y = cur[1];
    int cost = cur[2];

    for (int dir = 0; dir < 4; dir++) {

        int nx = x + dx[dir];
        int ny = y + dy[dir];

        int nextCost = cost + map[nx][ny];

        if (nextCost < dist[nx][ny]) {
            dist[nx][ny] = nextCost;
            pq.offer(new int[] {nx, ny, nextCost});
        }
    }
}
```

### 코드 흐름
1. 가장 비용이 작은 위치 꺼내기
2. 상하좌우 확인
3. 이동했을 때 새로운 비용 계산
4. 기존 비용보다 작으면 갱신
5. PriorityQueue에 삽입

### 시각화 / 레이아웃
- 왼쪽: 코드
- 오른쪽: ①~⑤ 단계 설명

### 발표 포인트
전체 소스코드를 설명하지 않고,
다익스트라가 실제로 동작하는 핵심 부분만 보여준다.

# 5. 실제로 어떻게 동작할까?

## Slide 13. 실제로 돌려보자 — 초기 상태

### 목적
앞에서 설명한 알고리즘이 실제 격자에서 어떻게 시작되는지 보여준다.

### 예제

```text
0 1 5
2 1 2
4 1 0
```

### 초기 dist

```text
0  ∞  ∞
∞  ∞  ∞
∞  ∞  ∞
```

### PriorityQueue

```text
[(0,0) : 0]
```

### 시각화 / 레이아웃
3분할:
- map
- dist
- PriorityQueue

### 발표 포인트
`dist[0][0] = 0`에서 시작하고 나머지는 충분히 큰 값으로 초기화한다.

---

## Slide 14. 실제 동작 — Step 1 ~ Step 3

### 목적
PriorityQueue와 dist가 실제로 어떻게 변하는지 보여준다.

### Step 1
현재:
```text
(0,0), cost = 0
```

갱신 후:

```text
0  1  ∞
2  ∞  ∞
∞  ∞  ∞
```

PriorityQueue:

```text
(0,1) : 1
(1,0) : 2
```

다음 탐색:
```text
(0,1)
```

이유:
> 현재 후보 중 누적 비용이 가장 작기 때문

### Step 2
`(0,1)`에서 주변 칸 갱신

예:

```text
0  1  6
2  2  ∞
∞  ∞  ∞
```

### 이후
같은 방식으로 2~3단계 정도만 보여주고 나머지는 생략한다.

### 시각화 / 레이아웃
- 한 슬라이드에서 애니메이션으로 단계별 표시하거나
- 필요하면 Step 1 / Step 2를 별도 슬라이드로 분리

### 발표 포인트
이 파트에서는 말보다 시각화가 중요하다.
현재 위치, 갱신되는 칸, PriorityQueue의 최소값을 색이나 강조로 구분한다.

---

## Slide 15. 최종적으로 최소 비용 도착

### 목적
실행 과정과 최종 답을 연결한다.

### 핵심 내용

```java
dist[N - 1][N - 1]
```

가 시작점에서 목적지까지의 최소 복구 시간이 된다.

### 설명
- 가장 비용이 작은 후보부터 탐색
- 더 저렴한 경로가 발견되면 갱신
- 이 과정을 반복
- 최종적으로 목적지의 최소 비용을 얻음

### 시각화 / 레이아웃
- 최종 dist 배열
- 최소 비용 경로를 격자 위에 표시
- 목적지 값 강조

### 발표 포인트
앞에서 배운 `PriorityQueue`, `dist`, 갱신 과정이 모두 이 결과로 연결된다는 점을 정리한다.

# 6. 코테에서 다익스트라를 알아보는 방법

## Slide 16. 이런 표현이 보이면 다익스트라를 의심하자

### 목적
문제 하나를 푸는 것을 넘어 다른 문제에도 적용할 수 있는 판단 기준을 전달한다.

### 키워드
- 최단 거리
- 최소 비용
- 최소 시간
- 누적 비용
- 이동마다 서로 다른 비용

### 판단 흐름

```text
최소 비용 문제인가?
        ↓
그래프로 표현 가능한가?
        ↓
이동마다 비용이 존재하는가?
        ↓
비용이 서로 다른가?
        ↓
음수 가중치가 없는가?
        ↓
Dijkstra 고려
```

### 시각화 / 레이아웃
- 체크리스트 또는 플로우차트 형태

### 발표 포인트
“다익스트라라는 단어가 문제에 나오지 않아도 조건을 보고 판단해야 한다”를 강조한다.

---

## Slide 17. BFS와 다익스트라 구분하기

### 목적
실전에서 가장 자주 헷갈리는 BFS와 다익스트라를 비교한다.

### 비교표

| 상황 | 알고리즘 |
|---|---|
| 단순 도달 여부 | DFS / BFS |
| 모든 이동 비용 동일 | BFS |
| 이동 비용이 서로 다르고 음수 없음 | Dijkstra |
| 음수 간선 존재 | Bellman-Ford 등 |

### 핵심 문장
> **격자 문제라고 무조건 BFS가 아니다.**

### 추가 설명
중요한 것은 문제의 모양이 아니라 **간선 비용의 구조**다.

### 시각화 / 레이아웃
- 표를 중심으로 구성
- 마지막 핵심 문장을 크게 강조

### 발표 포인트
발표에서 가장 기억에 남길 한 문장을 고른다면 이 문장을 사용한다.

# 7. 마무리

## Slide 18. 정리

### 목적
발표의 핵심 내용을 짧게 다시 묶는다.

### 핵심 정리

1. 보급로는 **가중치가 존재하는 최단 경로 문제**다.
2. BFS는 최소 이동 횟수는 구할 수 있지만 비용 최소를 보장하지 않는다.
3. 다익스트라는 **현재 누적 비용이 가장 작은 후보부터 탐색**한다.
4. `dist`와 `PriorityQueue`를 이용해 더 저렴한 경로를 계속 갱신한다.
5. 격자 문제도 그래프로 바라볼 수 있다.

### 마지막 문장
> **문제의 형태가 아니라, 비용 구조를 보고 알고리즘을 선택하자.**

### 시각화 / 레이아웃
- 핵심 4~5줄만 배치
- 마지막 문장을 크게 강조
