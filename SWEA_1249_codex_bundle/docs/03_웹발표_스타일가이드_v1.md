# SWEA 1249 보급로 — 웹 발표 스타일 가이드

> 버전: Style Guide v1  
> 상태: 확정 디자인 방향  
> 목적: 웹 발표 전체에서 시각적 일관성과 가독성을 유지하기 위한 디자인 기준

---

# 1. 최우선 원칙

이 웹은 일반 웹앱이나 대시보드가 아니라 **16:9 슬라이드 여러 장으로 구성된 웹 기반 프레젠테이션**이다.

디자인 우선순위:

```text
1. 알고리즘 이해 / 가독성
2. PPT 슬라이드다운 정돈된 구성
3. 필요한 순간의 동적 시각화
4. 보급로 문제의 분위기
5. 2.5D 효과
```

화면을 “있어 보이게” 만드는 것보다 **지금 설명하는 개념이 무엇인지 즉시 보이는 것**을 더 중요하게 생각한다.

---

# 2. 확정 스타일 키워드

> **Minimal Presentation × Engineering Illustration × Subtle 2.5D Motion**

한국어로 풀면:

> **깔끔한 알고리즘 발표 자료 + 아주 약한 공병/도로 복구 콘셉트 + 필요한 곳만 입체감과 움직임**

---

# 3. 절대 금지 사항

## 3-1. 의미 없는 슬로건 / 장식용 문구 금지

다음과 같이 발표 내용과 직접 관련 없는 문구를 **절대 임의로 추가하지 않는다.**

```text
“가장 안전한 길을, 다시 연결하다.”
“더 나은 내일을 위한 알고리즘”
“최적의 길을 찾아서”
“Mission Complete”
“Route Recovery for a Better Tomorrow”
```

이런 문구는 디자인을 꾸미기 위한 장식일 뿐 발표 이해에 도움을 주지 않는다.

### 엄격한 규칙

> **문서에 없는 슬로건, 캐치프레이즈, 감성 문구, 브랜드 문구를 AI가 임의로 만들어 넣지 않는다.**

허용되는 텍스트는 원칙적으로 다음뿐이다.

- 발표 제목
- 섹션 제목
- 현재 슬라이드의 핵심 문장
- 알고리즘 용어
- 코드
- 계산 과정
- 문제에 실제로 필요한 라벨
- `SWEA 1249 · 보급로` 같은 최소한의 문맥 표시
- 페이지 / 진행 번호

## 3-2. 웹앱처럼 보이는 UI 금지

기본 슬라이드에서 다음을 상시 노출하지 않는다.

- 왼쪽 사이드바 목차
- 대시보드형 다중 카드
- 과도한 상태 패널
- 상시 노출되는 설정 버튼
- 큰 하단 컨트롤 바
- 불필요한 메뉴
- 웹서비스용 Header / Navigation

필요한 UI는 발표 중 마우스를 움직였을 때만 나타나거나, 알고리즘 실행 Scene처럼 **정말 필요한 장면에서만** 등장한다.

## 3-3. 과한 테마 표현 금지

보급로 문제라고 해서 다음처럼 만들지 않는다.

- 군사 HUD
- 레이더 화면
- 사이버펑크
- 네온 Grid
- 전술 지휘실 Dashboard
- 과도한 군용 아이콘
- 카모플라주 패턴
- 계속 움직이는 배경
- 지나친 Glow

문제의 배경은 **아주 약한 시각적 모티프**로만 사용한다.

---

# 4. 슬라이드 기본 형식

모든 발표 화면은 16:9 비율을 유지한다.

권장 기준:

```text
1920 × 1080
```

브라우저 크기에 따라 동일 비율로 확대/축소한다. 전체화면에서는 브라우저 UI가 사라지고 슬라이드만 보이게 한다.

---

# 5. 슬라이드 기본 레이아웃

```text
┌─────────────────────────────────────────────────────────┐
│ 03 | 다익스트라 알고리즘                  SWEA 1249 · 보급로 │
│                                                         │
│ 현재까지 비용이 가장 작은 정점부터 탐색한다              │
│                                                         │
│                                                         │
│                  핵심 시각 자료                           │
│                                                         │
│                                                         │
│                                                   03 / 18 │
└─────────────────────────────────────────────────────────┘
```

### 원칙

- 왼쪽 상단: 섹션 번호 + 짧은 섹션명
- 오른쪽 상단: `SWEA 1249 · 보급로` 정도만 작게
- 큰 제목 또는 핵심 문장
- 중앙: 해당 슬라이드의 핵심 시각 자료
- 오른쪽 아래: 작은 페이지 번호
- 그 외 장식 텍스트 없음

---

# 6. 한 슬라이드에 한 메시지

한 장에서 모든 내용을 보여주지 않는다.

예:

```text
Slide A  다익스트라의 핵심 원리
Slide B  dist 초기화
Slide C  1번 정점에서 주변 정점 확인
Slide D  다음 정점은 무엇인가?
Slide E  Relaxation
```

각 슬라이드는 하나의 질문 또는 하나의 답을 중심으로 구성한다.

---

# 7. 배경

기본 배경:

```text
White
또는
아주 연한 Cool Gray / Blue Gray
```

예상 톤:

```text
#FFFFFF
#F8FAFC
#F5F8FC
```

어두운 배경을 기본으로 사용하지 않는다.

## 보급로 콘셉트 배경 요소

허용:

- 아주 연한 도로 곡선
- 작은 공병 장비 실루엣
- 약한 지형선
- 아주 옅은 격자
- 도로 단면의 추상적인 선
- 작은 공사/도로 아이콘

배경 대비는 약 `3~8%` 수준으로 두며 콘텐츠보다 먼저 눈에 들어오면 안 된다.

특히 **배경 요소 옆에 별도의 감성 문구를 넣지 않는다.**

---

# 8. 색상 역할

색상은 장식보다 **알고리즘 상태 표현**을 위해 사용한다.

- Text: Dark Navy / Charcoal
- Neutral: Pale Blue Gray / Gray
- Primary: Clear Blue
- Start: Warm Yellow
- Goal: Soft Red / Coral
- Current Node: Strong Blue
- Normal Node: Light Blue Gray
- Candidate: Blue outline
- Relaxation Success: Green
- No Update: Orange
- Inactive Edge: Gray
- Active Edge: Blue

색상 수를 최소화한다.

---

# 9. 2.5D 표현 규칙

입체감은 **시각 자료에만** 사용한다.

허용:

- 그래프 Node가 살짝 떠 있는 원형 디스크
- Tile이 살짝 올라오는 효과
- 부드러운 그림자
- 현재 Node가 약간 Lift
- 숫자가 바뀔 때 Number transition
- 간선을 따라 이동하는 작은 빛

금지:

- UI 카드 전체를 3D로 만들기
- 과한 Perspective
- 카메라를 계속 움직이기
- 회전하는 Node
- 입체 효과 때문에 텍스트가 왜곡되는 구성

---

# 10. 그래프 스타일

## Node

- 단순한 원형
- 아주 약한 입체감
- 번호를 크게
- dist는 Node 위 또는 가까운 위치에 작은 값으로 표시
- 현재 Node만 강하게 보이게 한다

## Edge

- 얇고 명확한 방향 화살표
- Weight는 간선 근처 작은 라벨
- 겹치지 않도록 Layout 설계
- 현재 확인하는 간선만 진하게

---

# 11. 애니메이션 원칙

평소 슬라이드는 거의 정적이다.

> **사용자가 다음 Step을 눌렀을 때 필요한 요소만 움직인다.**

예:

- Node가 6~10px 정도 위로 Lift
- 간선을 따라 작은 빛 이동
- Weight 1회 Pulse
- `∞ → 3`
- `5 → 4`
- PQ 카드 재정렬
- 최종 경로를 따라 빛 이동

## 가장 중요한 모션

### Relaxation

```text
5
↓
4
```

숫자 Replace가 아니라 Number transition을 사용한다.

### PriorityQueue

```text
3 : 2
2 : 3
4 : 5
```

값이 작은 카드가 자연스럽게 위로 정렬된다.

### Edge Traversal

Source에서 Target 방향으로 짧은 빛이 이동한다.

---

# 12. 알고리즘 실행 화면

일반 슬라이드에서는 상태 패널을 숨긴다.

실행 Scene에서만 필요에 따라 오른쪽 25~30%에 다음을 보여준다.

```text
Current Node
Priority Queue
dist
현재 계산
```

패널 역시 여러 카드로 쪼개지 않고 하나의 깔끔한 정보 영역처럼 보이게 한다.

---

# 13. PPT 슬라이드쇼 동작

필수:

```text
→ / Space / PageDown : 다음
← / PageUp           : 이전
Home                 : 처음
End                  : 마지막
F                    : 전체화면
ESC                  : 전체화면 종료
```

마우스를 일정 시간 움직이지 않으면 컨트롤은 숨긴다. 슬라이드 자체에 상시 표시되는 큰 버튼은 사용하지 않는다.

---

# 14. 전환 효과

기본:

- 짧은 Fade
- 짧은 Slide
- 요소 Morph

권장 시간:

```text
400~700ms
```

## 특별 전환

### Road → Grid
도로 단면 또는 지도 이미지가 축소되고, 카메라가 위에서 내려다보는 느낌으로 Grid로 전환.

### Grid → Graph
각 칸 중심에 Node가 생기고 상하좌우 연결선이 나타난다.

### Graph → Grid
다익스트라 일반 설명 후 Node가 정렬되며 격자 Tile로 Morph.

이 전환은 개념 연결을 위한 기능이며 장식용으로 남용하지 않는다.

---

# 15. Typography

한글이 우선이다.

- 굵은 제목
- 중간 굵기의 본문
- 작은 보조 라벨

한 슬라이드에서 Font Weight는 2~3종만 사용한다.

긴 문단을 사용하지 않는다. 핵심 문장은 1~2줄 안에서 끝낸다.

---

# 16. 텍스트 양 기준

한 슬라이드에서 기본적으로:

```text
제목        1개
핵심 문장   1~2줄
보조 설명   최대 3~4개
```

그 이상 필요하면 다음 슬라이드로 나눈다.

---

# 17. 확정 샘플 이미지 기준

현재 확정한 시각 방향은 다음 이미지와 같은 톤이다.

```text
a_clean_flat_modern_presentation_slide_landscap.png
```

유지할 요소:

- 밝고 깨끗한 배경
- 넓은 여백
- 큰 제목
- 한눈에 들어오는 그래프
- 약한 2.5D Node
- 소량의 Blue accent
- 하단/모서리의 아주 옅은 도로·공사 이미지
- 오른쪽 상단의 작고 절제된 문제 정보
- PPT 슬라이드다운 전체 구성

반드시 수정할 요소:

- 우측 설명 패널은 필요할 때만 사용
- 한 장의 정보량을 더 줄임
- 쓸데없는 Footer 문구 삭제
- 슬로건 / 감성 문구 완전 금지
- 컨트롤은 상시 표시하지 않음

---

# 18. 최종 디자인 판단 질문

새로운 요소를 추가하기 전에 다음을 확인한다.

```text
이 요소가 알고리즘 이해에 필요한가?
```

YES → 추가 가능  
NO → 삭제

그리고:

```text
이 문구가 실제 발표 내용에 있는가?
```

YES → 사용 가능  
NO → 특히 슬로건 / 캐치프레이즈라면 추가 금지
