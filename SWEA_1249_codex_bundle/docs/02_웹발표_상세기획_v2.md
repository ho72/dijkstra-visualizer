# 0. 웹 발표의 기본 방향

## 발표 형태

일반 웹사이트나 대시보드가 아니라 **PowerPoint 슬라이드쇼처럼 동작하는 16:9 웹 프레젠테이션**으로 만든다.

항상 한 화면에는 한 장의 슬라이드만 표시한다.

```text
16:9 Slide
→
다음
→
16:9 Slide
```

스크롤 기반 웹페이지는 사용하지 않는다.

### 기본 조작

```text
→ / Space / PageDown   다음
← / PageUp             이전
Home                   첫 슬라이드
End                    마지막 슬라이드
F                      전체화면
ESC                    전체화면 종료
R                      현재 동적 Scene 초기화
P                      자동 실행 / 일시정지
```

마우스용 컨트롤은 필요하지만 **발표 화면에 항상 크게 노출하지 않는다.**

마우스를 움직였을 때만 하단 또는 우측 하단에 작게 나타나고, 일정 시간이 지나면 다시 숨긴다.

# 1. 확정 디자인 스타일

웹 발표 전체는 별도 문서 `SWEA_1249_웹발표_스타일가이드_v1.md`를 기준으로 한다.

## 스타일 정의

> **Minimal Presentation × Engineering Illustration × Subtle 2.5D Motion**

즉:

> **깔끔한 PPT 알고리즘 발표 자료 + 아주 약한 보급로/도로 복구 콘셉트 + 필요한 곳만 2.5D 모션**

이다.

### 우선순위

```text
1. 알고리즘 이해와 가독성
2. PPT 슬라이드다운 구성
3. 동적 시각화
4. 보급로 문제의 분위기
5. 2.5D 효과
```

## 1-1. 의미 없는 슬로건 / 장식 문구 절대 금지

다음과 같은 문구를 절대 임의로 생성하지 않는다.

```text
“가장 안전한 길을, 다시 연결하다.”
“더 나은 내일을 위한 알고리즘”
“최적의 길을 찾아서”
```

> **문서에 실제로 존재하지 않는 슬로건, 캐치프레이즈, 감성 문구, 브랜드성 문구를 디자인 목적으로 추가하지 않는다.**

허용되는 텍스트는 발표 제목, 섹션 제목, 실제 설명, 알고리즘 용어, 코드, 계산식, 필요한 라벨, `SWEA 1249 · 보급로`, 진행 번호 정도로 제한한다.

## 1-2. 웹앱 / Dashboard 느낌 금지

기본 슬라이드에서 다음은 사용하지 않는다.

- 왼쪽 Sidebar
- Dashboard형 다중 Card
- 상시 상태 Panel
- 큰 Navigation Bar
- 큰 하단 Control Bar
- 설정 UI
- 장식용 Widget

알고리즘 실행 Scene처럼 정말 필요한 순간에만 상태 Panel을 사용한다.

## 1-3. 기본 화면 톤

- Background: White 또는 아주 연한 Cool Gray / Blue Gray
- Text: Dark Navy / Charcoal
- Main Accent: Clear Blue
- Start: Warm Yellow
- Goal: Soft Red / Coral
- Relaxation Success: Green
- No Update: Orange

보급로 콘셉트는 배경 모서리의 아주 옅은 도로, 공사 장비, 도로 단면, 격자, 지형선 정도로만 표현한다.

## 1-4. 한 슬라이드 = 한 메시지

한 Scene에 많은 정보를 우겨넣지 않는다.

```text
Slide 1  다익스트라의 핵심 아이디어
Slide 2  dist 초기화
Slide 3  1번 정점 주변 탐색
Slide 4  다음 정점 선택
Slide 5  PriorityQueue의 역할
Slide 6  Relaxation
```

필요한 정보가 많으면 다음 Slide로 분리한다.

## 1-5. 2.5D 사용 범위

입체 효과는 그래프 Node, Grid Tile, 현재 Node Lift, 부드러운 Shadow, 간선 이동 빛, 숫자 Transition 정도에만 사용한다.

UI Shell 자체는 평면적이고 정돈된 PPT 디자인을 유지한다.

## 1-6. 동적 효과

평상시에는 화면을 거의 정적으로 유지한다.

다음 Step을 눌렀을 때만:

- Node 활성화
- Edge traversal
- dist 값 변경
- PriorityQueue reorder
- Zoom / Focus
- Grid ↔ Graph morph

가 발생한다.

계속 움직이는 Decorative animation은 사용하지 않는다.

```text

↓

```

```text

```

### 발표자가 말할 내용

- 차량이 이동하려면 도로를 복구해야 한다.
- 도로 깊이에 비례해 복구 시간이 증가한다.

# 9. 예제 그래프의 시각 디자인

## 정점

각 Node는 약간 떠 있는 원형 플랫폼.

기본:

```text
   dist
    ∞

   (3)
```

### Node 구성

위:

```text
현재 dist
```

중앙:

```text
정점 번호
```

아래 또는 외곽 링:

```text
상태
```

### 상태

#### Idle
Neutral Gray.

#### Candidate
Blue / Cyan 얇은 링.

#### Current
약간 위로 Lift.

Shadow 증가.

#### Finished
작은 Check 또는 고정 Ring.

---

## Edge

방향 그래프이므로:

```text
──────▶
```

화살표가 명확해야 한다.

가중치:

```text
     2
──────▶
```

간선 중앙 또는 옆에 고정.

### Edge 상태

Idle:
- 얇음
- 낮은 대비

Inspecting:
- 두꺼워짐
- 작은 Light Dot이 Source → Target으로 이동

Relaxation Success:
- 잠시 Green pulse

Relaxation Fail:
- 잠시 Orange pulse
- 곧 기본 상태로 복귀

## Section A — Current

## Section B — Priority Queue

```text
PRIORITY QUEUE

┌─────────────┐
│ Node 2    3 │
├─────────────┤
│ Node 4    4 │
├─────────────┤
│ Node 4    5 │
└─────────────┘
```

최소값이 위로 보이게 한다.

PQ 내부 실제 Heap 구조까지 표현할 필요는 없다.

발표의 목적은:


# 32. Dijkstra Step Snapshot 구조 개념

구현 시 각 Step은 대략 다음 상태를 가진다.

```text
stepId

currentNode

dist[]

priorityQueue[]

activeEdge

comparison
  oldCost
  newCost
  success

nodeStates

edgeStates

message
```

예:

```text
STEP 6

currentNode = 3

activeEdge = 3 → 4

oldCost = 5
newCost = 4

success = true

dist[4] = 4

message =
"더 짧은 경로를 발견하여 dist[4]를 갱신합니다."
```

이 구조가 있으면:

```text
이전
다음
자동 재생
Reset
```

구현이 매우 쉬워진다.

# 34. 웹 발표에서 가장 중요한 장면

전체 발표 중 가장 공들여야 하는 장면은 다음 네 개다.

### 1위

```text
dist[4]
5 → 4
```

첫 Relaxation.

---

### 2위

```text
PQ
3:2
2:3
4:5
```

에서 `3`이 먼저 선택되는 장면.

---

### 3위

```text
2 → 3

5 > 2

NO UPDATE
```

갱신 실패.

---

### 4위

```text
dist[5]
11 → 10
```

두 번째 Relaxation.

이 네 장면만 명확하게 전달되어도
다익스트라의 핵심은 상당 부분 이해할 수 있다.
