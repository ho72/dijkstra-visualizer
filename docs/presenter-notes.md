# 알고리즘 발표 노트

## 설명 순서

대표 후보 목록 → 격자의 그래프 해석 → BFS의 탐색 순서 → 반례 → 보급로 조건에 맞는 다익스트라 선택.

후보 목록은 모든 알고리즘을 열거한 것이 아니라, 그래프 탐색과 최단 경로를 처음 비교할 때 사용하는 대표 사례다. 격자에서 상하좌우로 움직이는 모습 때문에 BFS가 자연스럽게 떠오를 수 있으므로 BFS의 기준을 별도로 설명한다. 가장 흔한 오답이라는 통계적 주장은 하지 않는다.

## 후보별 설명과 주의점

- DFS: 도달 가능 여부와 경로 탐색에 사용할 수 있다. 기본 DFS의 첫 경로가 최소 비용 경로인 것은 아니다. 모든 경로를 따지는 별도 탐색과 기본 DFS를 혼동하지 않는다.
- BFS: 모든 이동 비용이 같으면 최소 이동 횟수 경로가 최소 비용 경로다. 이 발표에서 비교하는 일반 BFS는 한 번 방문한 정점을 다시 갱신하지 않는 방식이다.
- Dijkstra: 음수 가중치가 없는 그래프의 단일 출발점 최단 경로에 적합하다. 보급로에서는 이동할 칸의 값이 0~9이고 목적은 누적 복구 시간의 최소화이므로 조건에 부합한다.
- Bellman–Ford: 음수 간선이 있을 때도 검토하는 단일 출발점 최단 경로 알고리즘이다. 도달 가능한 음수 사이클이 있으면 유한한 최단 거리가 없을 수 있다. 보급로에도 적용 가능하지만, 우선순위 큐 다익스트라가 이 문제 조건에서 더 효율적이다.
- Floyd–Warshall: 모든 정점 쌍의 최단 경로를 구한다. 보급로에서 필요한 것은 한 출발점에서 목적지까지의 비용이므로 계산 범위가 과하다. 시간 O(V³), 거리 저장 공간 O(V²)도 격자 전체에 적용하기에는 부담스럽다.

"BFS로 절대 못 푼다"고 설명하지 않는다. 일반 큐를 사용하더라도 더 작은 비용을 발견할 때마다 다시 넣어 완화하는 방식은 가능하다. 다만 이는 한 번 방문하면 끝내는 일반 BFS와 다른 최단 경로 접근이며, 최소 비용 후보를 우선 선택하는 다익스트라와도 탐색 순서가 다르다.

## 근거 자료

- [Princeton Algorithms — Undirected Graphs](https://algs4.cs.princeton.edu/41graph/): DFS의 도달 가능성 탐색과 BFS의 최소 간선 수 경로.
- [Princeton Algorithms — Shortest Paths](https://algs4.cs.princeton.edu/44sp/): 비음수 비용 다익스트라, 완화, Bellman–Ford와 큐 기반 구현, 복잡도 비교.
- [Princeton Algorithms — FloydWarshall API](https://algs4.cs.princeton.edu/code/javadoc/edu/princeton/cs/algs4/FloydWarshall.html): 모든 정점 쌍 최단 경로와 음수 사이클 조건, 시간·공간 복잡도.

## 다익스트라 챕터 진행

- 14: 예제의 목표는 1에서 6까지의 최소 비용이다. 화살표는 방향, 간선의 숫자는 비용이다. 1번의 이웃에 든 비용 3·2·5 중 2인 후보를 먼저 선택한다.
- 15: dist는 현재까지 발견한 최선이다. 시작점 0, 나머지 ∞에서 시작한다. 정점 4의 값은 5에서 4로 바뀌지만 아직 확정하지 않았다. 아래 표의 ‘확정’은 유효한 최소 후보를 꺼낸 정점에만 붙는다.
- 16: PQ에는 (정점, 넣을 당시 비용)을 기록한다. 최신 비용표 dist와 처리할 후보 목록 PQ의 역할을 구분한다. 화면은 이해를 돕기 위해 비용순으로 정렬해 보여준다. 실제 힙 내부가 완전히 정렬된 배열이라는 뜻은 아니다.
- 17: 한 번의 반복을 먼저 설명한다. 후보를 꺼내고, 오래된 기록이면 건너뛴다. 유효한 후보라면 모든 인접 간선의 새 비용을 계산한다. 작아지면 dist를 고치고 PQ에 추가한다. 모든 이웃을 확인한 뒤 다음 후보로 간다.
- 18–19: 새 경로 1→3→4는 2+2=4로 기존 직접 경로 5보다 작다. dist 갱신과 새 PQ 후보 추가를 한 사건으로 설명한다. 반대로 새 비용이 크거나 같으면 둘 다 변경하지 않는다.
- 20: 예제에서 최소 후보는 정점 3의 비용 2, 다른 후보의 비용은 3과 5다. 정점 2까지 이미 비용 3이고 이후 간선은 모두 0 이상이므로, 2를 거치는 경로가 2보다 작아질 수 없다. 실제 1→2→3도 3+2=5다. 따라서 2→3을 확인하기 전에 유효한 최소 후보 (3,2)를 꺼낼 때 dist[3]을 확정하며, 나중에 2→3을 비교해도 갱신하지 않는다. 일반적으로 이미 확정한 영역에서 미확정 영역으로 넘어가는 첫 정점은 완화된 후보이며, 최소 후보보다 먼저 더 싼 경로가 숨어 있을 수 없다는 원리다. 비용 동률과 0인 간선도 허용된다. 음수 간선이 있으면 이 확정 논리를 사용할 수 없다. 근거: 위 Princeton Shortest Paths의 완화·비음수 다익스트라 설명.
- 21: 정점 4의 기록만 확대한다. 다섯 단계는 (4,5) 기록 → 개선 후 (4,4) 추가 → 비용 4 후보를 먼저 처리 → (4,5)를 poll → 5>dist[4]=4 비교 후 건너뛰기다. PQ 안에서는 후보를 미리 오래됨으로 표시하거나 취소선을 긋지 않는다. 논리적으로 이미 더 좋은 값이 있더라도, 실제 코드는 후보를 꺼낸 뒤 비용을 비교하여 처리 여부를 판단한다. 이 확대 화면에서 정점 4의 기록이 없어져도 전체 PQ가 비었다는 뜻은 아니다.
- 22: 앞서 배운 규칙을 17개 주요 사건에 적용한다. 매번 위의 관찰 문구를 읽고 그래프·dist·PQ 중 변한 부분을 짚는다. 처음 세 이웃을 기록하는 단계만 묶고, 이후의 갱신 성공·실패와 오래된 후보 처리는 모두 보여준다. 11→10 재갱신도 여기에서 다룬다. (4,5)와 (5,11)은 각각 꺼내기 → 비용 비교 후 건너뛰기를 별도 표시 단계로 보여주며, 두 단계 사이에서 거리와 확정 상태는 바뀌지 않는다.
- 23: 경로 1→3→4→5→6과 비용 11을 확인한다.
- 24: 발표자가 제공한 `Programmers_dijkstra_2.solution(n, start, roads)`의 핵심을 발췌했다. 그래프 구성, distance 초기화, PQ 초기화, 최소 후보 꺼내기, 꺼낸 비용 비교, 인접 정점 확인, 새 비용 계산·비교, 갱신·추가의 8단계다. 코드는 그래프 구성·초기화·탐색 반복으로 나눠 보여주며 같은 메서드 안에서 이어지는 코드다. 개념 설명의 dist가 실제 코드의 distance라는 점을 연결한다. `graph`의 `{to, cost}`는 간선 비용이고 PQ의 `{nextNode, newDistance}`는 누적 비용이다. `currentDistance`는 PQ에 넣을 당시 값이며 최신 distance[now]보다 크면 건너뛴다. 별도의 Node·Edge 클래스로 바꾸지 않았다. package, imports, main, 출력문, 반환 배열 정리는 핵심 발췌에서 생략했다. 사용자 코드처럼 PQ가 빌 때까지 실행하며, 예제의 정점 1~6 거리는 0, 3, 2, 4, 10, 11이다. 실제 목적지 조기 종료는 오래된 후보를 거른 유효한 최소 후보의 pop 이후에만 한다.

## 보급로 코드와 격자 실행

- 26–27: 정점 번호가 `(x,y)` 좌표로, `distance[v]`가 `minCost[x][y]`로 바뀐다. 이 코드에서 x는 행, y는 열이다. 가중치는 도착할 칸의 `map[nextX][nextY]`다.
- 28: 발표자가 제공한 `SWEA_1249`를 기준으로 좌표와 PQ, 최소 비용표 초기화, 최소 후보 꺼내기, 오래된 후보 검사, 목적지 종료, 상하좌우 탐색, 새 비용 비교, 갱신·추가의 8단계를 설명한다. PQ의 `{x,y,비용}` 중 `[2]`가 누적 비용이다. `Queue` 변수에 들어 있는 실제 객체는 비용순 `PriorityQueue`다. 두 번째 코드 화면의 열린 while문이 세 번째 코드 화면까지 이어진다. 방향 배열은 위·아래·왼쪽·오른쪽 순서다. 파일 입력 설정과 입출력 코드는 핵심 발췌에서 제외했다.
- 30–31: 목적지 `(2,2)`를 비용 3인 유효한 최소 후보로 꺼내는 시점에 종료한다. 총 16개 표시 단계이며, 남은 후보 3개를 지우거나 큐가 비었다고 설명하지 않는다. 목적지의 최소 비용은 확정됐지만 다른 모든 칸의 비용을 확정해야 하는 것은 아니다. 그림의 체크는 이미 확정된 칸에만 붙는다. 비용이 같은 후보의 표시 순서는 정점 번호로 통일하며, 사용자 코드에서 동률의 처리 순서가 달라도 최단 비용은 같다.
