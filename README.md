# SWEA 1249 · 보급로

React + TypeScript + Vite로 만든 **37장, 16:9 인터랙티브 웹 발표**입니다.
발표 내용과 기존 자료는 `SWEA_1249_codex_bundle/`에 보존했습니다.

## 실행

```sh
npm install
npm run dev -- --port 5189
```

브라우저에서 `http://localhost:5189`를 엽니다.

```sh
npm test
npm run build
npm run preview -- --port 5189
```

의존성을 설치한 뒤에는 로컬 실행에 인터넷 연결이 필요 없습니다. 운영 빌드는 최초 접속 시 모든 이미지와 Three.js 청크를 Service Worker에 저장합니다. 저장이 완료된 브라우저에서는 오프라인 새로고침도 가능합니다. 처음부터 오프라인인 새 기기, 브라우저 저장 공간을 차단한 환경에서는 로컬 서버를 이용하세요. `dist/index.html`을 `file://`로 직접 여는 방식 대신 HTTP 서버로 제공합니다.

## 발표 조작

| 키                   | 동작                                                 |
| -------------------- | ---------------------------------------------------- |
| → / Space / PageDown | 다음 단계, 마지막 단계에서는 다음 슬라이드           |
| ← / PageUp           | 이전 단계, 첫 단계에서는 이전 슬라이드의 마지막 단계 |
| Home / End           | 처음 / 마지막 슬라이드                               |
| F / Esc              | 전체화면 / 브라우저 전체화면 종료                    |
| R                    | 현재 장면 전체 초기화                                |
| P                    | 현재 장면 자동재생 / 정지                            |
| ?                    | 단축키 도움말                                        |

마우스를 움직이거나 키보드로 컨트롤에 포커스하면 우측 하단의 작은 조작부가 나타납니다. 단계 슬라이더로 임의 시점에 이동할 수 있고, 건너뛰기 버튼으로 현재 장면을 생략할 수 있습니다. 오래된 PQ 후보 장면도 이 버튼으로 건너뜁니다. 자동재생은 현재 장면에서만 동작하며, 다른 탭으로 이동하면 정지합니다.

일반 화면에서는 왼쪽에 37장 전체의 캡처 썸네일과 번호를 표시합니다. 각 이미지는 실제 슬라이드 첫 단계의 960×540 JPEG이며, 제목은 툴팁과 접근성 이름으로 제공합니다. 현재 슬라이드를 파란 테두리로 강조하고 목록을 자동으로 스크롤합니다. 이미지를 선택하면 자동재생을 멈추고 해당 슬라이드의 첫 단계로 이동합니다. 목록에서는 ↑/↓, Home/End로 포커스를 옮기고 Enter/Space로 선택합니다. 선택 후에는 발표 영역으로 포커스가 돌아갑니다. 목록 상단 전체화면 버튼 또는 F를 누르면 목록을 숨기며, 전체화면을 종료하면 현재 위치를 유지한 채 다시 표시합니다.

URL `?scene=22&step=11`처럼 **1-based** 슬라이드·단계 번호로 직접 열 수 있습니다. 현재 위치는 URL에 반영되어 새로고침해도 복원됩니다. 자동재생 여부는 복원하지 않습니다.

## 발표 구성

| 슬라이드 | 내용                                                                  |
| -------- | --------------------------------------------------------------------- |
| 01–02    | 표지 · 7개 챕터 목차와 시작 페이지                                    |
| 03–06    | 문제 이해 전환 · 문제 상황과 깊이=복구 시간 · 이동 규칙 · 목표        |
| 07–12    | 알고리즘 선택 전환 · 후보 목록 · 그래프 해석 · BFS · 반례 · 선택 근거 |
| 13–16    | 다익스트라 전환 · 최소 비용 우선 · dist · Priority Queue              |
| 17–19    | 반복 구조 · 5→4 갱신과 PQ 추가 · 갱신하지 않는 경우                  |
| 20–21    | 비음수 비용과 확정 근거 · PQ에 이전 후보가 남는 이유                  |
| 22–24    | 전체 실행 17개 주요 사건 · 최종 경로 11 · Java 템플릿                 |
| 25–28    | 보급로 적용 전환 · Graph→Grid · 좌표/가중치 대응 · 보급로 Java 코드   |
| 29–31    | 격자 실행 전환 · 3×3 격자 실행: 16개 주요 스냅샷 · 최종 비용 3        |
| 32–34    | 코테에서 알아보기 전환 · 판단 조건 · BFS 비교                         |
| 35–36    | 정리 전환 · 핵심 복습                                                 |
| 37       | 감사합니다. · 발표 마무리                                            |

보급로 격자 실행은 선택·갱신 중심으로 보여주며, 목적지를 유효한 최소 후보로 꺼내면 종료합니다. 남은 PQ 후보는 그대로 표시합니다. 생략하지 않은 전체 실행은 비교 검증용 `allGridSteps`에 보존되어 있습니다.

방향 그래프 전체 실행은 첫 정점의 이웃 초기화를 묶고, 이후의 모든 선택·갱신·갱신 실패·오래된 후보 처리를 순서대로 보여줍니다. 11→10 재갱신은 이 실행에 포함합니다. 원본 26개 간선 확인 스냅샷은 `graphSteps`에 그대로 보존하며, 발표에는 `graphPresentationSteps`의 17개 사건을 사용합니다. 오래된 후보 두 건은 각각 꺼내기와 비용 비교 후 건너뛰기를 분리한 표시 단계가 추가됩니다. PQ 안의 후보에는 미리 오래됨을 표시하지 않습니다. PQ는 화면 축소 배율과 무관한 로컬 행 위치로 한 번만 이동하며, 큐 영역의 높이를 고정합니다.

## 구현 구조

- `src/app/`: 슬라이드 상태 reducer, 키보드·전체화면·자동재생
- `src/slides/`: 37장 구성, 공통 챕터 정의, 알고리즘 후보, 발표용 Java 코드와 단계 설명
- `src/dijkstra/`: 방향 그래프, 격자 어댑터, 순수 실행 함수, 스냅샷, 검증
- `src/components/`: SVG 그래프·격자, dist, PQ, 비용 비교
- `src/three/`: 그래프→격자 전환에만 사용하는 Three.js 장면
- `src/styles/`: 밝은 배경·큰 한글 제목·제한된 상태색
- `src/build/`: 운영 빌드의 오프라인 캐시 생성
- `public/code/Solution.java`: 컴파일 가능한 SWEA 전체 예제

스냅샷은 서로 배열·객체를 공유하지 않고, PQ 동률은 비용→정점→삽입순으로 결정합니다. 유효 후보를 선택하면 최소 거리를 확정하며, 오래된 후보를 꺼낸 경우에는 dist를 바꾸지 않습니다. 모션은 스냅샷을 표시하는 역할만 합니다.

1920×1080 Stage를 목록을 제외한 표시 영역에 contain 스케일링합니다. 전체화면에서는 목록이 사라진 전체 영역을 사용하며, ResizeObserver로 영역 크기 변경을 반영합니다. Three.js는 한 장면만 지연 로딩하며 `frameloop="demand"`로 필요한 전환에만 렌더링합니다. WebGL 실패 시 SVG 대체 화면을 사용합니다. `prefers-reduced-motion` 설정에서는 이동 모션을 최소화합니다.

## 내용상 적용한 판단

- 기존 슬라이드 디자인을 유지하며, 일반 화면에만 요청한 슬라이드 목록을 표시합니다. 전체화면에서는 슬라이드만 표시합니다.
- 깊이 설명은 문제 상황 페이지에 통합했습니다. 목차와 7개 챕터 전환 페이지, 알고리즘 후보 목록과 “감사합니다.” 마무리 페이지를 추가하여 총 37장입니다. 발표자 이름은 제공되지 않아 임의로 기입하지 않았습니다.
- 알고리즘 선택은 대표 후보 → 격자의 그래프 해석 → BFS의 기준 → 반례 → 다익스트라 선택 순서입니다. 일반 BFS와 큐 기반 반복 완화의 차이, 다른 후보의 적용 가능성은 `docs/presenter-notes.md`에 근거 자료와 함께 정리했습니다.
- 뒷자리 가독성을 위해 보조 설명은 주로 28–32px, 본문은 32–38px로 확대했습니다. Java 코드는 28px로 통일하고 빈 줄 간격을 줄여 전체 코드가 잘리지 않도록 했습니다. 수치는 1920×1080 Stage 기준입니다.
- 다익스트라 Java 설명은 발표자가 제공한 `Programmers_dijkstra_2`의 `solution`에서 발췌했습니다. `int[]`와 원래 변수명을 유지하며, 그래프 구성·초기화·탐색 반복의 세 코드 화면을 8단계로 설명합니다. 출력·반환 배열 정리는 생략했습니다.
- 보급로 Java 설명과 전체 예제는 발표자가 제공한 `SWEA_1249`의 알고리즘으로 맞췄습니다. `dx`, `dy`, `minCost`, `currentCost`, `newDistance`와 `Queue<int[]>`를 유지하며, 초기화·후보 검사와 종료·상하좌우 탐색의 세 코드 화면을 8단계로 설명합니다. 방향 배열은 위·아래·왼쪽·오른쪽 순서이고, x는 행, y는 열입니다. `System.setIn`은 제외했습니다. 전체 예제의 클래스명은 기존 `Solution`을 유지하고 알고리즘을 `solve`로 분리했습니다.
- 기존 도로 깊이·격자 이미지를 재사용했습니다. 알고리즘 그림은 SVG이며 생성 이미지를 추가하지 않았습니다.
- 3D는 개념 대응 장면에만 사용하고, 실제 격자 실행은 선명한 숫자와 약한 높이감을 가진 SVG로 표시합니다.

## 검증

슬라이드 내용이 바뀌면 `scripts/capture-slide-thumbnails.js`를 Playwright CLI의 `run-code --filename`으로 실행해 썸네일을 다시 생성합니다. 먼저 개발 서버의 일반 화면을 열어 두어야 합니다. 결과는 `output/playwright/slide-thumbnails/`에 저장되며, 확인 후 `public/slide-thumbnails/`에 복사하고 다시 빌드합니다. 캡처 중에만 목록과 조작부를 숨기며 발표 코드는 변경하지 않습니다. 파일명은 페이지 순서 대신 슬라이드 ID를 사용합니다.

`npm test`는 35개 검증을 수행합니다. 문서의 모든 핵심 갱신, 정확한 간선·PQ 순서·최종 경로, 과거 스냅샷 독립성, 비용 0·순환·단일 칸, 80개 고정 시드 격자와 독립 Bellman–Ford 비교, 이전/다음 역연산, Reset·자동재생·URL 범위를 확인합니다. 실제 37장 구성의 모든 단계와 챕터 경계, 목차 순서, 알고리즘 선택 순서, 다익스트라 학습 순서, 축약 실행의 사건 보존, 갱신과 확정의 구분도 검증합니다. 후보를 꺼낸 뒤 비교하는 순서와 그 사이의 거리·확정 상태 보존, PQ 안에서의 사전 판정 표시가 없는지도 검증합니다. Java 코드 발췌의 원래 변수·자료구조 유지, 단계별 코드 범위와 강조 줄, 전체 보급로 코드와 발췌의 일치, 목적지 조기 종료 시 남은 PQ와 상태 보존도 확인합니다. 탐색 목록은 37개 항목과 현재 페이지의 정적 렌더링, JPEG 이미지 파일의 존재와 완전성, 키보드 포커스 범위, 선택 시 단계·재생 상태와 URL 복원, 표시 영역에 맞는 배율 계산을 검증합니다.

Java 예제는 `javac`로 컴파일하고 문서의 3×3 격자, 1×1, 비용 0 격자, 비용이 다른 2×2 격자에서 각각 3, 0, 0, 1을 확인했습니다.

초기 구현에서는 화면 비율, 1920×1080 / 1440×810 / 1024×768에서의 표시, 이전 단계 복원, Reset, 자동재생·정지, Space, Home, 전체화면 F·Esc, 도움말 포커스를 확인했습니다. 운영 미리보기 서버를 실제 중단한 후 새로고침하고 아직 방문하지 않은 Three.js 장면을 열어 오프라인 캐시도 검증했습니다. 글씨 확대 당시에는 27장의 마지막 단계에서 콘텐츠 범위를 확인했습니다.

목차·챕터 추가 후에는 36장 전체의 마지막 단계에서 콘텐츠 범위와 페이지 번호를 재검사했습니다. 목차, 7개 챕터 전환, 알고리즘 선택의 5개 페이지는 실제 화면으로 확인했고, 선택 근거의 단계별 공개와 챕터 경계의 이전/다음 복원도 검증했습니다. 하단 여백이 좁았던 dist·실행 페이지는 글자 크기를 유지하면서 도식 높이와 설명 위치를 조정했습니다.
